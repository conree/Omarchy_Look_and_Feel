Current status: read-only appearance prototype. The bar panel inventories apps and catalogs and exposes transaction status, recovery, and rollback. Apply is disabled because no reviewed application adapter is registered. No application appearance settings have been changed and the plugin is not installed/enabled in the live bar.

Implemented

  • Canonical settings schema and unselected example cover separate system/terminal typography, Light/Dark themes, automatic mode, independent background and icons, and manual schedule coordinates/offsets.
  • transaction.py implements journaled file changes, rollback, recovery before a new Apply, and status reporting. Its application target allowlist is intentionally empty.
  • The QML panel shows transaction status, recovery IDs/errors, recovery and rollback actions, and a disabled Apply state while adapters are unavailable.
  • controller.py discovers priority applications and font/theme/background/icon catalogs. Catalog IDs are deterministic. The catalog eligibility gate requires verified provenance, a license and evidence reference, and theme compatibility review.
  • Current inventory audit: 616 records total — 31 themes, 364 font families, 74 icon themes, and 147 backgrounds. Zero are selectable; available metadata does not establish adequate license/provenance evidence.
  • solar_schedule.py calculates apparent sunrise/sunset offline and selects the next Light/Dark transition using coordinates, an IANA time zone, and independent event offsets. It does not run persistently or apply themes.

Independent checks completed

  • qmllint Panel.qml completed without diagnostics.
  • All 616 inventory records validated against catalog-entry.schema.json; the schema rejected a record marked selectable without review evidence.
  • Python AST parsing and HTML parsing completed for the changed source/document artifacts.
  • Solar outputs for three 2026 New York dates were compared against NOAA's published table; the rounded times were within two minutes. This is an approximate calculator, not a live scheduler.

  3. After a theme adapter and eligible Light/Dark themes exist, implement the persistent scheduler and route transitions through the transaction core.
